Ways to cut your AI coding bill

Most of what AI coding costs comes from a handful of habits, not from how much you get done. Change those, and the same work costs less, whether you pay per token or against a plan's limits.

Updated 23 November 2026 · 6 min read

Measure first

Before changing anything, find out where the cost actually goes. In Claude Code, /usage shows your plan limits or your session's cost, and /context shows how full the current chat is. Over a week, look at your totals per day and per chat. Usually one or two chats account for a large share, and they nearly always have something in common: they ran for a long time, on the biggest model, with a huge context.

The rest of this guide is about those three things.

Keep chats short and focused

Every message you send carries the whole conversation with it. In a fresh chat that's cheap. Two hours in, with files, test output and earlier attempts piled up, each small question costs many times more.

  • Clear between tasks. When you move on to something unrelated, use /clear. The old context won't help with the new task, and it makes every request bigger.
  • Compact long ones. When you need to keep going on the same task, /compact swaps the history for a summary. Tell it what matters, for example /compact keep the database schema and the failing test.
  • Keep noisy output out. Long logs and full test runs end up in the context. Ask for just the failures, or use hooks that filter verbose output before Claude sees it.

Use the right model for the job

Model choice is the biggest single lever. Prices per token differ several times over between the smallest and largest models. Anthropic's own advice for Claude Code is to use Sonnet for most coding and save Opus for complex architecture decisions or problems that need many steps of reasoning.

  • Switch with /model when the task changes, not just once at the start.
  • Give simple subagents a small model, such as Haiku, if you set up your own.
  • Turn extended thinking down with /effort for routine edits. Thinking tokens are billed like any others.

Trim what's sent with every request

Some text goes with every single request, so it's worth keeping lean:

  • CLAUDE.md. Anthropic suggests keeping it under 200 lines. Move instructions you only need for one kind of work, such as release steps or a migration checklist, into skills that load only when needed.
  • MCP servers. Each connected server adds its tool descriptions to the context. Disconnect the ones you aren't using with /mcp, and where a simple command-line tool does the same job, prefer it.

Say what you want, then check early

Vague requests lead to exploring, guessing and redoing, and all of that is paid for. A few habits cut it down:

  • Be specific. Name the file, the function and what "done" looks like. "Add input validation to signup() in auth.ts and a test for an empty email" costs far less than "improve the signup code".
  • Plan first. Plan mode (Shift+Tab) has Claude look around and propose an approach before editing anything. Fixing a plan is cheap. Undoing a wrong implementation isn't.
  • Stop it early. If a reply heads the wrong way, press Escape or use /rewind rather than waiting for it to finish.
  • Give it a way to check its work. A test to pass or a command to run lets the model confirm it's done, instead of you going back and forth.

Be careful with parallel agents

Subagents and agent teams keep your main chat tidy, but each one makes its own requests, and they all count. A team of four agents can use four times what one would. Use them when the work really splits into independent parts, keep teams small, and use Sonnet for teammates.

Outside Claude Code

If you also pay for APIs directly, through OpenAI or OpenRouter for example:

  • One key per tool, with a cap. A spending limit on each key turns a runaway script into a stopped tool instead of a surprise bill.
  • Cheaper models for bulk work. Summarising, tagging and simple extraction rarely need the most capable model.
  • Batch what can wait. Many providers offer a batch option for requests that don't need an answer right away, at a lower price.
  • Look at the bill weekly. Spend creeps up quietly. A weekly look catches it while it's still small.
