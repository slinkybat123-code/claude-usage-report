How to track your OpenRouter spending

OpenRouter makes it easy to try any model with one balance, which also makes it easy to lose track of where the balance went. Here's how to see it, and how to put a cap on it.

Updated 23 November 2026 · 5 min read

How the money works

You buy credits on OpenRouter, and every request takes the price of the model you used out of that balance. The price depends on the model and on how many tokens went in and came out. A cheap model and an expensive one can differ by a hundred times for the same prompt, so a single tool switching models can change your spend more than doubling your usage would.

Because one balance pays for everything, the useful questions are: which key spent it, on which model, and on which day? OpenRouter can answer all three.

Check a key's spend with the API

Any OpenRouter API key can ask about itself:

curl https://openrouter.ai/api/v1/key \
  -H "Authorization: Bearer $OPENROUTER_API_KEY"

The answer includes, among other fields:

  • usage: everything this key has spent, in credits
  • usage_daily, usage_weekly and usage_monthly: the same for recent periods
  • limit, limit_remaining and limit_reset: the key's spending cap, if it has one, what's left of it and when it resets

That's enough to answer "what did this tool cost me this week?" without opening the website, as long as each tool has its own key.

Your whole balance needs a management key

To see your account's total, use GET /api/v1/credits. It returns total_credits (everything you've bought) and total_usage (everything you've spent). The difference is your balance.

This endpoint needs a management key. A normal key gets a 403 with "Only management keys can perform this operation". Management keys are a separate kind of key, made for creating and managing your other keys, so they're more powerful than a normal one. Keep one only where you need it, and store it like a password.

Put a cap on each key

OpenRouter supports per-key credit limits: an optional spending cap set on an individual API key. When a key reaches its cap, it stops working until the limit resets or you raise it. Your other keys keep going. Two habits make caps really useful:

  • One key per tool or project. Your coding assistant, a side project and a script you're testing each get their own key. Then the per-key figures tell you exactly what each one costs.
  • Caps on anything experimental. A script stuck in a loop, or an agent left running overnight, can spend a surprising amount. A small cap on its key turns that into a stopped tool instead of a surprise bill.

Set the cap when you create a key, or edit an existing key in your OpenRouter settings. Check the current options there, since OpenRouter can add new kinds of limits, such as budgets that reset.

See where it went: activity

Your OpenRouter account has an activity view, with usage broken down by model and by day. It's the quickest way to spot the one model that's quietly most of your bill.

The same breakdown is available from the API's activity endpoint, which returns rows per day and model with tokens, requests and cost. Like the credits endpoint, it needs a management key. A tracker given only a normal key can still show that key's spend from /api/v1/key, just not the per-model detail.

Free models count too, in their own way

Free models don't take anything from your balance, but they aren't unlimited. They have a daily allowance of requests. The /api/v1/key answer includes a free_model_daily_requests entry with how many you've used today, the limit and what's left. If a tool suddenly starts failing on a free model, that's the first thing to check.

It's also worth knowing when a tool quietly falls back from a free model to a paid one. The activity breakdown by model shows that straight away: a paid model you didn't expect, with a cost next to it.

A simple routine

  1. Give each tool its own key, with a cap you'd be comfortable losing.
  2. Once a week, look at activity by model. Swap the most expensive model for a cheaper one wherever it does the job just as well.
  3. Top up on purpose rather than with automatic top-ups, at least until you know your usual spend.
