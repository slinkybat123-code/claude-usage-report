Claude Code's 5-hour and weekly limits, explained

On a Pro or Max plan, Claude Code doesn't charge you per token. You get an allowance instead, measured two ways. Here's what each limit means and how to make them last.

Updated 23 November 2026 · 6 min read

The two limits

Anthropic's help centre puts it simply: Pro and Max plans have a five-hour session limit and a weekly limit. Think of them as two buckets that fill as you work:

  • The five-hour limit caps how much you can do in a short burst. It protects against one long, heavy session using everything at once.
  • The weekly limit caps your total over a week, so steady daily use can still run out before the week is over.

Other plans differ a little. Anthropic lists Ultra with a weekly limit only, and Max and Ultra also have a separate weekly limit for Fable models. Plans and numbers change from time to time, so check Anthropic's current help article on using Claude Code with your Pro or Max plan rather than relying on numbers you saw online.

Shared with the rest of Claude

The limits aren't just for Claude Code. They're shared across Claude, so chats on claude.ai and in the Claude apps come out of the same allowance, and so does Claude Code running inside your editor. If you spent the morning on a long research chat in the browser, you'll have less left for coding in the afternoon.

To see where you stand, type /usage in Claude Code. On a plan, it shows a bar for each limit, how much of it you've used, and when it resets. The reset time on that screen is the one to trust. Don't try to work it out from memory.

What uses them up fastest

Your allowance goes down with the work the model does, not with the number of messages you send. A few things make each message much bigger than it looks:

  • Long chats. Every request sends the whole conversation again. Prompt caching makes that cheaper, but a chat with a full context window still costs far more per message than a fresh one.
  • The biggest models. Anthropic's own advice is to use Sonnet for most coding and save Opus for the hard problems. The largest models use your allowance faster.
  • Extended thinking. Thinking tokens are real tokens. High effort on a simple task is wasted allowance.
  • Subagents and agent teams. They're handy for keeping your main chat clean, but their requests count against your usage too, and a team of several agents uses several times as much.
  • Unused MCP servers. Every connected server adds its tool descriptions to the context of every request, whether you use them or not.
  • Noisy tool output. A test run or log that prints thousands of lines lands in the context and stays there.

When you hit a limit

Claude Code tells you when you've reached a limit. According to Anthropic's help article, you then have three choices:

  1. Wait for the reset. /usage shows when that is. For the five-hour limit that's a matter of hours at most. For the weekly limit it may be days.
  2. Turn on usage credits, so you can keep going and pay for the extra usage.
  3. Switch to a Console account and pay for API credits instead.

If you pay extra, keep an eye on it. Extra usage is billed per token, so the habits below start saving real money, not just allowance.

Habits that make your limits last

Most of these come straight from Anthropic's guide to managing costs in Claude Code, and they work just as well for stretching a plan:

  • Clear between tasks. /clear starts fresh when you move on to something unrelated. Old context only makes each request bigger.
  • Compact long chats. /compact replaces the history with a summary. You can tell it what to keep, for example /compact keep the API design decisions.
  • Pick the model for the job. Switch with /model. Small, clear tasks rarely need the largest model.
  • Turn thinking down with /effort for routine work.
  • Keep CLAUDE.md short. Anthropic suggests under 200 lines. It's sent with every request, so every line costs you each time. Move instructions you only need for one kind of task into skills.
  • Disconnect MCP servers you aren't using with /mcp.
  • Plan first. Plan mode (Shift+Tab) lets Claude look around and propose an approach before it starts editing, which avoids expensive wrong turns.
  • Stop it early. If a reply heads the wrong way, press Escape, or use /rewind, instead of letting it finish and then asking for a redo.

Keep an eye on your pace

The limits are easiest to manage when you notice early. Look at /usage at the start of a big task, and again halfway through. If you've used most of the five-hour limit in the first hour, slow down or switch to a smaller model, instead of finding out mid-task.
