How to see your OpenAI API usage (and why it needs an admin key)

If you've tried to read your OpenAI usage with your normal API key and got "access denied", the key isn't broken. It's the wrong kind. Here's the difference, and how to set up the right one.

Updated 23 November 2026 · 5 min read

Two kinds of key

OpenAI keeps two jobs apart:

  • API keys call the models. Project keys start with sk-proj-, and service account keys belong to a project too. They're what your apps and coding tools use.
  • Admin keys start with sk-admin-. They manage your organization: members, projects, and reading usage and costs.

That's why a project key gets an HTTP 401 or 403 from the usage endpoints. It isn't allowed to see organization-wide figures. It works the other way round too: OpenAI's documentation says admin keys can't be used for anything except administration endpoints, so you can't use one to call a model. Keep both, each for its own job.

Making an admin key

  1. Sign in at platform.openai.com → Settings → Organization → Admin keys. You need to be an owner of the organization. If you can't see the page, ask whoever owns your OpenAI organization.
  2. Choose Create new admin key and give it a name you'll recognise later, such as "usage tracking".
  3. If you're offered a choice of permissions, read-only access to usage is all a tracker needs. A key that can only read can't change anything if it leaks.
  4. Copy the key straight away. Like other OpenAI keys, it's shown once. If you lose it, make a new one and revoke the old one.

An admin key can see your whole organization, every project and every member. Treat it like a password, and never put it in code, a chat with an AI, or a public bug report.

What the usage and costs endpoints give you

With the admin key, two endpoints answer most questions:

  • GET /v1/organization/usage/completions returns token counts in time buckets (for example one per day): input, output and cached tokens and the number of requests. You can group them by model or by project.
  • GET /v1/organization/costs returns what you were charged, in dollars, per bucket and line item. This is the number that matches your invoice.

A quick test from a terminal looks like this, with the key in an environment variable rather than typed into the command:

curl "https://api.openai.com/v1/organization/costs?start_time=1794787200&limit=7" \
  -H "Authorization: Bearer $OPENAI_ADMIN_KEY"

start_time is a Unix timestamp in seconds. The answer is JSON with a data list of buckets. Longer ranges come in pages, so follow the next_page value until there isn't one.

Usage and costs measure different things. Usage is what you did, in tokens. Costs is what you pay for it. When they don't seem to agree, it's usually because different models price tokens very differently, or because some costs, such as tools or storage, aren't token-based at all.

No code? Use the dashboard

For a one-off look you don't need a key at all. Signed in to the OpenAI platform, the Usage page shows your spend and tokens over time, and lets you filter by project and model. It's the same data the endpoints return.

The API is for when you want the figures somewhere else: a spreadsheet, a weekly report, or a dashboard that also shows your other AI tools. That's when an admin key earns its keep, because it lets a tool fetch the figures on its own, without you signing in each time.

Common errors and what they mean

You seeUsually means
401 UnauthorizedThe key is mistyped, revoked, or not an admin key.
403 with "insufficient permissions" or "missing scopes"A project or service account key, or an admin key without read access to usage.
An empty data listNo usage in that time range, or the key belongs to a different organization than the one you used.
Today looks lowRecent usage can take a little while to appear. Check again later before worrying.

Keeping the key safe

  • Store it in an environment variable or a password manager, not in a file inside a project folder.
  • Give it its own name, so you know what to revoke if you stop using a tool.
  • If you think it leaked, revoke it on the same Admin keys page right away. That takes effect at once.
  • Only give it to tools you trust to read usage and nothing else.
