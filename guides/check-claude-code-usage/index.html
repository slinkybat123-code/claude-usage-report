How to check your Claude Code usage

Claude Code can tell you a lot about what you've used, if you know where to look. Here are the built-in commands, the files it keeps on your computer, and what the numbers in them mean.

Updated 23 November 2026 · 5 min read

Start with /usage

In any Claude Code session, type /usage and press Enter. (/cost is another name for the same command.) What you see depends on how you pay for Claude Code.

  • On a Pro, Max, Ultra, Team or Enterprise plan, it shows bars for your plan limits and a breakdown of what counts against them. This is the number that decides whether you can keep working, so it's the one to watch.
  • On API billing, the Session block shows the tokens this session has used and what they cost. Anthropic's documentation describes that block as meant for API users.

If you're on a subscription and also see a dollar figure, read it as "what this would have cost through the API". It isn't a bill. Your plan price stays the same however much of it you use.

One thing to check: if the ANTHROPIC_API_KEY environment variable is set on your computer, Claude Code uses that key, and your usage is billed to the API instead of your plan. Anthropic's help pages call this out specifically. /status shows which account you're using.

Two more commands worth knowing

/context draws the current context window as a coloured grid: how much is your conversation, how much is tool definitions and instructions, and how much is free. It matters for usage because every new request sends the whole context again. A chat that has grown to fill most of the window costs far more per message than a fresh one, even though each message looks small to you.

/status opens Claude Code's settings on the Status tab, with your version, model, account and connection. Use it when the numbers don't look right. A different model or account than you expected explains a lot of surprises.

Neither command keeps a history. They tell you about now, so for "what did I use last week?" you need the files below.

What Claude Code keeps on your computer

Every chat is saved as a transcript in your home folder:

~/.claude/projects/<project>/<session>.jsonl

On Windows that's %USERPROFILE%\.claude\projects. Each project folder you've worked in gets its own folder, and each chat is one .jsonl file, where every line is one event: a message from you, a reply, a tool call or a tool result. Claude's replies carry a usage block with the token counts for that request.

Two things to know before you rely on these files:

  • They're deleted after a while. Claude Code removes transcripts older than the cleanupPeriodDays setting, which is 30 days by default. If you want a longer history, raise it in your Claude Code settings before the old files go.
  • They contain your conversations, including any code or secrets that passed through a chat. Don't attach them to a bug report or send them to anyone.

Reading the numbers

Each request's usage block has four counts, and they're priced very differently:

CountWhat it is
Input tokensNew text sent to the model in this request.
Cache writesContext stored so later requests can reuse it. These cost a little more than plain input, once.
Cache readsContext reused from the cache. Much cheaper than input, and usually the biggest count by far.
Output tokensWhat the model wrote back, including tool calls. The most expensive tokens, per token.

Claude Code uses prompt caching automatically, which is why a long chat shows enormous cache-read numbers. That's normal, and much cheaper than resending everything as fresh input. Still, cache reads add up when the context is huge, which is the practical reason to start a new chat for a new task.

To turn tokens into dollars, multiply each count by the model's price for that kind of token. Prices are per million tokens and differ a lot between models, so the model matters as much as the token count. A morning on the largest model can cost several times the same work on a smaller one.

Tools that add it up for you

Adding up thousands of lines by hand isn't realistic, so several tools read the same transcript files for you:

  • Command-line tools such as ccusage print daily or monthly totals in your terminal. They're free, quick, and good for a monthly look back.
  • Dashboards keep watching the files and show totals as you work, often with charts per day, per project and per model.

Whichever you use, the figures are only as complete as the files. A tool can't count a chat Claude Code has already cleaned up, which is another reason to raise cleanupPeriodDays if history matters to you.

A quick routine

  1. Glance at /usage when you start a long piece of work, so you know how much room you have.
  2. Check /context when a chat starts to feel slow or long, and start fresh if most of the window is used.
  3. Once a week, look at your totals per day and per project, to spot the one task that used half your allowance.
